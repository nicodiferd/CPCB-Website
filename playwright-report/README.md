# Playwright Test Reports

This directory contains **HTML test reports** generated by Playwright after running the test suite.

---

## What This Directory Is For

When you run Playwright tests, detailed HTML reports are automatically generated and saved here. These reports provide:

- **Test Results** - Pass/fail status for every test
- **Screenshots** - Visual evidence of test execution (especially on failures)
- **Traces** - Step-by-step execution traces for debugging
- **Performance Metrics** - Test duration and timing information
- **Error Details** - Stack traces and error messages for failed tests

---

## Viewing Reports

### After Running Tests

```bash
# Run tests (report auto-generated)
npm test

# View the report
npm run test:report
```

This opens an interactive HTML report in your browser at `http://localhost:9323`

### Manual Access

If the automatic viewer doesn't open:

1. Navigate to this directory
2. Open `index.html` in a web browser
3. Browse through test results interactively

The generated report includes:

### Main Index Page
- **Summary Statistics** - Total, passed, failed, skipped tests

### Test Details
- **Individual Test Results** - Click any test to see details
- **Screenshots** - Visual snapshots at key moments
- **Traces** - Timeline of actions and assertions

### Filtering & Search
- Filter by status (passed/failed/flaky)
- Search by test name
- Group by file or project

## When Reports Are Generated

Reports are created automatically:

1. **After every test run** - `npm test` generates a new report
2. **On CI/CD pipelines** - When tests run in GitHub Actions (future)
3. **Manual generation** - `npx playwright test --reporter=html`

---

## Report Configuration

Report settings are defined in `playwright.config.ts`:

```typescript
reporter: [
  ['html', { outputFolder: 'playwright-report' }],
  ['list'],
]
```

### Options

- **outputFolder** - Where reports are saved (this directory)
- **open** - Auto-open browser after tests (`'never'`, `'always'`, `'on-failure'`)
- **host** - Host for report server
- **port** - Port for report server (default: 9323)

## Understanding Test Results

### Test Status Indicators

- ✅ **Passed** - Test executed successfully, all assertions passed
- ❌ **Failed** - Test failed, check error details and screenshots
- ⚠️ **Flaky** - Test passed on retry (inconsistent)
- ⊘ **Skipped** - Test was skipped (test.skip() used)

### Reading Failure Details

When a test fails, the report shows:

1. **Error Message** - What went wrong
2. **Stack Trace** - Where the error occurred
3. **Screenshot** - Visual state at time of failure
4. **Trace** - Step-by-step execution leading to failure

---

## Debugging with Reports

### Using Traces

1. Click on a failed test
2. Click "View trace" link
3. See timeline of:
   - Actions performed
   - Assertions checked
   - Network requests
   - Console logs
   - Screenshots at each step

### Using Screenshots

- **on-failure** - Captured when tests fail (default)
- **always** - Captured for every test
- **never** - No screenshots

Configure in `playwright.config.ts`:
```typescript
use: {
  screenshot: 'only-on-failure',
}
```

## Cleaning Up Reports

### Delete Old Reports

Reports can accumulate and take up space. To clean:

```bash
# Delete all reports
rm -rf playwright-report/*

# Keep only README.md
find playwright-report -type f ! -name 'README.md' -delete
```

### Automatic Cleanup

Reports are overwritten on each test run, so old data is automatically replaced.

## Troubleshooting

### "Report not found" Error

```bash
# Regenerate report
npm test
npm run test:report
```

### "Port already in use" Error

```bash
# Kill existing report server
lsof -ti:9323 | xargs kill -9

# Or use a different port
npx playwright show-report --port 9324
```

### Empty Report

If the report is empty:
1. Ensure tests ran successfully
2. Check for errors in test execution
3. Verify reporter configuration in `playwright.config.ts`

## Best Practices

1. **Review Reports After Every Test Run** - Don't ignore failures
2. **Use Traces for Debugging** - Much faster than re-running tests
3. **Share Reports with Team** - Export and send for collaboration
4. **Archive Important Reports** - Before major releases or changes
5. **Don't Commit Reports to Git** - Too large, auto-generated
